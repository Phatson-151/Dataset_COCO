# PART 1 — Dataset และ Experimental Setup

## 1.1 Dataset

ใช้ **Microsoft COCO 2017 Dataset** จาก `data/` ใน GitHub Repository ที่เชื่อมไว้ โดยเริ่มจาก subset ที่มีอยู่จริง และดาวน์โหลด/จัดเตรียมข้อมูลเพิ่มเติมเฉพาะเมื่อ Cloud รองรับและมีสิทธิ์เข้าถึงข้อมูล (อย่าสมมติว่า dataset ใน repo มีครบ COCO ทั้งชุด) กำหนดคลาสเป้าหมายทั้งหมด 4 คลาส:

| Class ID | Class      |
| -------- | ---------- |
| 0        | Background |
| 1        | Person     |
| 2        | Car        |
| 3        | Motorcycle |

Background หมายถึงพิกเซลที่ไม่ใช่สามคลาสเป้าหมาย โดยต้องสร้างจาก Segmentation Ground Truth อย่างถูกต้อง และกำหนดวิธีจัดการพื้นที่ Ignore, Crowd, Unannotated Regions และ Overlapping Annotations อย่างชัดเจน

ห้ามใช้ Ground Truth ช่วยแก้ Prediction, ลบ False Positives หรือเลือกจุด Activation ในขั้นตอน Inference

## 1.2 Image Resolution

**ต้องใช้ภาพความละเอียดต้นฉบับจริง (Original / Native Resolution)**

ข้อกำหนด:

- ห้าม Resize ภาพเป็น 64×64, 128×128 หรือขนาดอื่นก่อนฝึก
- ห้ามใช้ภาพย่อเป็นข้อมูลหลักในการ Train, Validation หรือ Test
- ใช้ภาพ RGB ต้นฉบับ และสร้าง Ground Truth Masks ในพิกัดเดียวกับภาพ
- หากต้องใช้ Tiled Processing เพื่อจัดการหน่วยความจำ ต้องตัด Tiles จากพิกเซลต้นฉบับโดยตรงโดยไม่มี Downsampling
- ใช้ Overlapping Tiles และ Boundary Handling เมื่อเหมาะสม
- ทำนายและประเมินบนพิกัดความละเอียดต้นฉบับ
- ไม่ใช้การขยาย Score Maps จากภาพขนาดเล็กเป็นผลลัพธ์หลัก

ให้พยายามทำ Full-image Optimization ตาม Paper หากทรัพยากรรองรับ หากต้องใช้ Tiled/Streaming Approximation ต้องอธิบายอย่างชัดเจนว่าแตกต่างจาก Global Optimization อย่างไร และไม่เรียกผลว่า Exact Full-image Optimization

## 1.3 Dataset Splitting

ใช้ TRAIN / VALIDATION / TEST อย่างเป็นระบบ

- TRAIN: ฝึก Dictionary, Sparse Codes และ Classifier
- VALIDATION: เลือก Hyperparameters, Dictionary Size, Gamma และ Threshold
- TEST: ประเมินผลสุดท้ายบนข้อมูลอิสระ

ต้องตรวจสอบ Image ID ไม่ให้ซ้ำกันระหว่างชุดข้อมูล

ให้ขยายจำนวนภาพมากกว่าเวอร์ชันก่อนหน้าที่ใช้ TRAIN 10 / VAL 3 / TEST 5 หาก Dataset มีภาพเพียงพอ โดยกำหนดจำนวนจริงตามข้อมูลที่เข้าถึงได้ และรายงาน Image IDs ทุกชุด

หาก TEST เดิมเคยถูกใช้ปรับโมเดล ต้องจัดชุด Final Holdout ใหม่ที่ไม่เคยถูกใช้เลือกโมเดล พร้อมระบุข้อจำกัดเมื่อไม่สามารถจัดข้อมูลใหม่ได้

ทุกการทดลอง CSC และ SCSC ต้องใช้ Data Split และหลักเกณฑ์การประเมินเดียวกัน

# PART 2 — Mathematical Formulation และ ADMM

## 2.1 CSC Baseline

ทำ CSC ตามสมการของ Paper โดยมี Reconstruction Loss, L1 Sparsity และ Dictionary Constraints

[
\min\_{D,Z}\frac12|X-D\*Z|\_2^2+\beta|Z|\_1
]

ใช้ Boundary Mask และ Unit-norm Dictionary Constraints ตามความเหมาะสมของ Paper

## 2.2 Supervised CSC

ทำ SCSC ตามแนวคิด Equation 5–8 ของ Paper:

[
\min\_{D,Z,\theta}
\frac12|X-D\*Z|\_2^2+
\beta|Z|*1+*
*\gamma\left(\mathcal{L}*{cls}(Y,Z,\theta)+\alpha|\theta|\_2^2\right)
]

ต้องมี Supervised Classification Loss ที่ส่งผลต่อ Sparse Coding ระหว่างการฝึกจริง ไม่ใช่ทำ CSC ก่อนแล้วเพียงนำ Logistic Regression มาต่อภายหลัง

ใช้ Logistic Regression Supervision ตาม Paper และขยายเป็น Multiclass โดยพิจารณา One-vs-All ตามต้นฉบับ พร้อม Background Handling อย่างชัดเจน

หากมีการใช้ Multinomial Softmax หรือแนวทางที่ต่างจาก Paper ให้แยกเป็น Experiment เพิ่มเติมและระบุว่าเป็น Extension ไม่ใช่การทำตามต้นฉบับโดยตรง

## 2.3 Optimization

ใช้ Alternating Optimization / Coordinate Descent ตาม Algorithm 2 ใน Paper ประกอบด้วย:

1. Supervised Sparse Coding Update (Z-step)
2. Dictionary Update (D-step)
3. Classifier Update (θ-step)

ใช้ FFT-based ADMM และวิธีแก้ Linear System ที่มีประสิทธิภาพตาม Paper และหลักการ SPORCO

## 2.4 ADMM Convergence

ปัญหาสำคัญจากเวอร์ชันก่อนคือ ADMM ไม่ Converge ครบทุก Batch

ต้องแก้และตรวจสอบ:

- Primal Residual
- Dual Residual
- Absolute / Relative Tolerance
- Objective Function
- Numerical Stability
- Dictionary Norm Constraints
- Warm Starts
- ADMM Penalty Parameter
- จำนวน ADMM Iterations
- การเปลี่ยนแปลงของ Loss ในแต่ละ Outer Iteration

ตั้งเป้าหมายให้ทั้ง CSC และ SCSC Converge ภายใต้เกณฑ์ที่กำหนดล่วงหน้า

สามารถเพิ่มเพดาน ADMM iterations เช่น 500, 1,000 หรือใช้ Adaptive Stopping ตามความจำเป็น

ห้ามรายงานว่า Converged เพียงเพราะครบจำนวน Iterations หรือผ่อน Tolerance จนผ่าน

หากมี Batch ที่ไม่ Converge ให้บันทึกสถานะจริงและวิเคราะห์

## 2.5 Outer Iterations

เพิ่มจากเวอร์ชันเดิม 5 รอบ เป็นอย่างน้อย **10 Outer Iterations**

สามารถทดลอง 10, 15, 20 หรือมากกว่านั้น หากผลลัพธ์ยังดีขึ้นและการคำนวณรองรับ

ให้ตรวจ:

- Reconstruction Loss
- Classification Loss
- Total Objective
- Validation AP / mIoU
- Dictionary Changes
- Convergence Ratio

ห้ามเลือกจำนวน Outer Iterations จากผล TEST

# PART 3 — Hyperparameter Experiments

ต้องทดลองตามรูปแบบ Paper ไม่ใช่ทดลอง Dictionary Size อย่างเดียว

## 3.1 Gamma Sweep

ทดลองค่า Classification Tradeoff γ หลายค่า

ตัวอย่างค่าเริ่มต้น:

`γ = [0, 0.05, 0.1, 0.15, 0.2, 0.5, 1, 2, 5, 10, 100]`

ค่า γ=0 ใช้เป็น CSC Baseline และค่าที่มากกว่าศูนย์ใช้สำหรับ SCSC

ตรวจสอบสเกลของ Loss ก่อน เพราะค่าที่เหมาะสมขึ้นอยู่กับการ Sum/Mean Loss, จำนวนพิกเซล และการ Normalization

หากค่าข้างต้นไม่เหมาะกับสเกลจริง ให้เพิ่มการค้นหาแบบ Logarithmic หรือช่วงที่ละเอียดขึ้น พร้อมอธิบายเหตุผล

สำหรับทุกค่า γ ต้องบันทึก:

- AP แยกแต่ละคลาส
- Macro AP / mAP
- PSNR
- SSIM เป็นผลเสริม
- IoU / mIoU
- Precision / Recall
- Background IoU
- Class Confusion
- ADMM Convergence
- Reconstruction / Classification Loss
- Runtime

ต้องเลือก γ ที่เหมาะสมจาก VALIDATION โดยไม่ใช้ TEST

## 3.2 Dictionary Size Experiment

ทดลองจำนวน Filters (K) หลายขนาด

ใช้ค่าเดิมเป็นจุดเริ่มต้น:

`K = [4, 8, 12, 16, 32, 49, 100]`

Paper มีการศึกษาจำนวน Filters 4, 16, 49 และ 100 ดังนั้นให้พยายามรวมค่าที่เปรียบเทียบกับ Paper ได้ด้วย

หากการฝึกบางขนาดใช้ทรัพยากรเกินข้อจำกัด ให้รายงานตามจริงและแสดงชุดที่ทดลองสำเร็จ

ทุก K ต้องเปรียบเทียบ CSC/SCSC ด้วยเงื่อนไขเดียวกัน

## 3.3 Number of Training Images Experiment

ทดลองจำนวนภาพฝึก (N) ตามแนว Figure 5(c) และ 5(f)

ตัวอย่าง:

`N = [1, 5, 10, 20, 40]`

Paper ใช้การเปรียบเทียบจำนวนภาพ เช่น 1, 10, 25, 40 ให้พยายามรวมค่าตาม Paper หาก Dataset เพียงพอ

ต้องวิเคราะห์ว่าการเพิ่ม Training Images ช่วยให้ SCSC มี Discriminability และ Generalization ดีขึ้นหรือไม่

ใช้ VAL/TEST ชุดเดิมระหว่างการทดลอง N และให้ Training Subsets เป็นแบบ Nested เมื่อเหมาะสม

## 3.4 Other Parameters

ทดลองหรือควบคุม:

- β: Sparsity Coefficient
- α: Classifier Regularization
- Filter Size เช่น 11×11 และ 21×21 ตามบริบทของ Paper
- Learning Rate / Classifier Solver
- Sampling Strategy
- Number of Positive/Negative Samples
- Number of Outer Iterations

ไม่จำเป็นต้องทำ Full Cartesian Grid ที่มีต้นทุนสูงเกินไป แต่ต้องมีวิธีคัดเลือกการทดลองที่ชัดเจน และไม่ละเลย Gamma, K, N ซึ่งเป็นแกนหลักของ Paper

# PART 11 — Fair Comparison Rules

ต้องเปรียบเทียบ CSC และ SCSC อย่างเป็นธรรมที่สุด

ข้อกำหนดสำคัญ:

- ใช้ภาพเดียวกันทุกการทดลองคู่
- ใช้ Train/Validation/Test Split เดียวกัน
- ใช้จำนวน Filters เดียวกันสำหรับการเปรียบเทียบแต่ละคู่
- ใช้ Filter Size เดียวกัน
- ใช้ Initialization หรือ Random Seed ที่ควบคุมได้
- ใช้ Outer Iterations และ ADMM Stopping Criteria ที่เทียบเคียงกันได้
- ฝึก Evaluation Classifier ใหม่แยกสำหรับ CSC และ SCSC
- ใช้วิธีสร้าง Classification Maps เดียวกัน
- ใช้ Color Scale และ Visualization Protocol เดียวกัน
- ใช้ Ground Truth เฉพาะส่วนที่อนุญาตในการฝึก/Calibration และการประเมิน
- ห้ามปรับ Threshold โดยดูผล TEST
- ห้ามซ่อน Failed Experiments หรือ Non-converged Runs

ถ้ามีการปรับปรุงเฉพาะ SCSC เช่น Class-balanced Sampling หรือ Special Postprocessing ต้องอธิบายความแตกต่างและทำ Ablation เพื่อไม่ให้เกิดการเปรียบเทียบที่ไม่เป็นธรรม

หากทำทั้งหมดไม่ได้ ให้ทำส่วนที่สำคัญที่สุดให้เสร็จจริงมากที่สุดภายในงานปัจจุบัน พร้อมส่งไฟล์ที่ตรวจสอบได้และรายการสิ่งที่ยังขาด ไม่ใช่หยุดแค่การเสนอแผน

## ข้อกำหนดเฉพาะสำหรับ Codex Cloud และ GitHub

- ทำงานบน **Cloud Environment** ที่เลือก Repository `Phatson-151/Dataset_COCO` เท่านั้น ไม่สั่งให้ฉันเปิด VS Code หรือรันบนเครื่องตัวเอง
- ใช้ Repository ที่มีอยู่ ไม่สร้าง Repo ใหม่ ไม่ขอให้อัปโหลด ZIP โปรเจกต์เดิมซ้ำ และไม่ถือว่าไฟล์จากแชท ChatGPT อื่น ๆ เข้าถึงได้โดยอัตโนมัติ
- ทำงานบน branch ใหม่เพื่อเก็บ baseline เดิมใน `main` เป็นหลักฐาน; ตรวจสอบ `git status`, `git diff` และ tests ก่อน commit/push
- ก่อนรัน Experiment Sweep ขนาดใหญ่ ตรวจสอบว่า Cloud มีเวลารัน/พื้นที่/Compute เพียงพอ; หากไม่พอให้ทำการทดลองที่ตรวจสอบได้จริงตามลำดับความสำคัญและเก็บ Checkpoints อย่างปลอดภัย
- ภาพใน Repo เดิมอาจมีเพียง subset 18 ภาพ หากต้องการ N=25/40 หรือ Validation/Test ที่ใหญ่ขึ้น ต้องจัดหา images และ annotation ที่ถูกต้องเพิ่มจริง ห้ามนำ image ID เดิมซ้ำเพื่อเพิ่ม N
- ตรวจว่า Cloud อนุญาตให้เข้าถึงอินเทอร์เน็ตสำหรับดาวน์โหลด COCO เพิ่มหรือไม่; หากทำไม่ได้ให้บันทึกข้อจำกัดอย่างชัดเจน
- โมเดล/ผลลัพธ์ขนาดใหญ่ที่เกิน GitHub limits ให้จัดเก็บเป็น Cloud Artifact หรือที่จัดเก็บที่เข้าถึงได้ แล้วใส่ Manifest, Checksum และวิธีเข้าถึงในรายงาน ไม่ commit binary เกินขีดจำกัดปกติของ GitHub
- อย่าสั่งให้ลบทุกไฟล์เดิมตั้งแต่เริ่ม: ให้รักษา source code, dataset และ reference PDFs ของ repo แล้วสร้าง `final output` ใหม่อย่างสะอาดสำหรับผลรันใหม่เท่านั้น
- รายงานทุก Experiment ว่า `completed`, `failed`, `not run` หรือ `inconclusive` และบันทึก Config/Seed/Version/Environment/Checkpoint/Log ประกอบ
- การฝึก Gamma Sweep, K Sweep และ N Sweep ต้องไม่ใช้ TEST เลือกโมเดล; ถ้าภาพ TEST เดิมเคยถูกเปิดดูเพื่อปรับระบบ ให้จัด independent holdout ใหม่เมื่อสามารถทำได้
- ความเหนือกว่าของ SCSC เป็น **สมมติฐานที่จะทดสอบ** ไม่ใช่ข้อกำหนดให้สร้างผลลัพธ์ที่ต้องชนะทุกคลาส
